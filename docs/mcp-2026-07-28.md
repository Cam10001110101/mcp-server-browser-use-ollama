# MCP 2026-07-28 support

This server targets the [2026-07-28 specification](https://modelcontextprotocol.io/specification/2026-07-28)
using the locked official Python SDK 2.3.0. The bundled client uses
`server/discover`, then sends per-request version, identity and capability
metadata. The server also accepts legacy initialization through the SDK's
compatibility path.

The implemented surface is stdio and ten browser tools. The server advertises
only tools. Resources, prompts, HTTP, subscriptions, tasks and server-initiated
interactions are not application features. Browser state uses explicit
`session_id` tool arguments; these are application handles, not protocol sessions.

Wire-level tests send raw JSON-RPC to the actual subprocess, independently of
the SDK client serializer. They verify requests before discovery, supported
versions, per-request errors and recovery, server identity, `resultType`, private
cache metadata, deterministic tools, JSON Schema 2020-12 definitions, and tool
errors. The SDK interoperability test covers both native discovery and legacy
initialization. Another test runs the bundled client and verifies it negotiated
the July revision rather than silently using a legacy handshake.

Run `uv sync --locked --extra dev` and `uv run --locked pytest -m 'not e2e'`.
CI runs these checks on Linux, macOS and Windows with Python 3.11–3.14, plus the
sandboxed Chromium security test on Linux. See [security remediation](security-remediation.md)
for the dependency audit and remaining security boundaries.

The tests establish coverage of this server's declared features; they do not
constitute an independent certification of universal “100% compliance.” Optional
MCP features need not be implemented to conform to the protocol.
